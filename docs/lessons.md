## 使用约定

- **时机**：每次修完缺陷、或做出有取舍的设计决策后，当天追加条目——趁记忆新鲜。
- **格式**：踩坑按「现象 → 根因 → 解决 → 沉淀」四段写。根因要追问到"当初为什么会写成/漏成这样"，不停在表面现象。
- **提炼**：条目若能升华出通用原则，同步归入「设计心得」并互相引用；心得必须挂着一个真实条目或提交作证据，不写空泛的"最佳实践"。
- **排序**：新条目插在最上，编号递增。

## 一、踩坑记录

### 3. 对话框残留到战斗画面（2026-08-31）

- **现象**：剧情对话结束后面板不收起，跨场景残留——换地图还在，进战斗还挂在操作界面上。
- **根因**：`Dialogue.say()` 只负责"显示一页并等待推进"，收起逻辑只写在 `choose()`（选项）的结尾；而所有剧情段落都以 `say()` 收尾，收起路径永远走不到。`Dialogue` 是跨场景存活的 autoload 画布层，把一个"没收尾"放大成了"穿场景 bug"。当初写成这样，是因为把"显示"和"收起"拆在了两个函数里，没有成对设计。
- **解决**：序列自动收起——每页推进后，若下一帧没有新台词/选项接续（剧情说完了）就隐藏面板；连续台词的隐藏与再显示在同一帧内，无闪烁。收尾收进系统内部，不靠每个剧情调用点自觉记住收尾。补 3 项冒烟回归（台词中保持 / 连续不收 / 结束自动收）。
- **沉淀**：见心得 [生命周期必须成对设计](#二设计心得好游戏是怎么设计出来的)。有"显示"就必须有"收起"，且收尾要放在所有调用路径的共用层，而不是指望调用方记得。

### 2. 全局类缓存过期：Could not find base class（2026-08-31，1100b6f）

- **现象**：编辑器会话早于新增文件时，进地图直接解析报错，进不去。
- **根因**：继承与静态调用依赖 `class_name` 全局类缓存（`.godot/` 下、不入版本控制）。缓存里没有 `MapBase`/`StoryEvents`，`extends MapBase` 与 `StoryEvents.xxx` 在解析期就失败。当初这么写是图省事——全局类名比路径引用干净；代价是把关键依赖押在一个可能过期的生成物上。
- **解决**：继承与跨模块引用一律按路径 preload：`extends "res://src/world/map_base.gd"`、`const Story := preload("res://src/story/story_events.gd")`。
- **沉淀**：见心得 [依赖显式化，不依赖隐式注册](#二设计心得好游戏是怎么设计出来的)。显式路径啰嗦一点，但对缓存状态、导入顺序免疫；越是"基础设施"级的引用越要显式。

### 1. 瓦片判定两处越界 + 地图实现复制膨胀（2026-08-31，ccea098）

- **现象**：越界判定失效，大片地图被误判成界外；同时 M1 的 test_wilds 有 400 行独立地图实现，M2 做第二、三张地图时眼看要每张复制一遍。
- **根因**：①地图是"每行 4 段、每段 10 格"的两级编码，判定代码把两级坐标搞混——行数误用 `rows.size() / CHUNK` 整除，列边界检查误用全局列号而非段内偏移。同一坐标有两种等价表示（全局格 vs 行-段-偏移），换算时口径用错。②当初 M1 求快把实现直接写在具体地图里，没有抽公共结构，复制膨胀是那时埋下的。
- **解决**：修正换算并注释写清编码结构；test_wilds 收敛为 `MapBase` 薄子类（62 行）；冒烟新增地图完整性校验（行数为 4 的倍数、出生点/触发点/传送门两端/精英格可通行）与 scene_smoke 全实例化验证。
- **沉淀**：见心得 [不变量测试化](#二设计心得好游戏是怎么设计出来的) 与 [第二个实例出现时就抽象](#二设计心得好游戏是怎么设计出来的)。字符串拼地图本质也是一种数据格式，格式约定（不变量）要么写成断言、要么写成自动校验，不能只活在作者脑子里。

## 二、设计心得：好游戏是怎么设计出来的

> 每条都挂着本项目的真实证据，新心得往上追加。

### 流程：怎么推进开发

| # | 心得 | 证据 |
| - | ---- | ---- |
| P1 | **文档先行，定案再动手**——方向性争议在文档里解决掉，不开工后反复改向；文档标"已定案"才立项写码 | GDD v0.2 定案（2026-08-31）当天才开工 M1；回合制 vs 即时、位阶制 vs 等级制都在文档阶段定死 |
| P2 | **垂直切片优先于横向铺量**——先让"探索→剧情→战斗→成长"整圈能转，再扩内容；每一步都可玩、可验证，验证不过就原地调，不带病前进 | M1 核心循环 → M2 切片 → M3 完整章节的三级推进；M2 里程碑明确挂着"待实机试玩调优"才准开 M3 |
| P3 | **占位素材先行**——玩法没验证前不投美术；但目录结构、命名规范提前定好，正式素材替换时不动代码 | `assets/images/` 全部为程序生成占位图；设计文档明确"占位素材先行"决策 |
| P4 | **冒烟测试当护栏**——无头测试随改随跑；修任何 bug 必须带回归测试，让每个踩过的坑变成一条永久断言 | 60 项冒烟 + 场景冒烟；对话框修复同步补 3 项回归 |
| P5 | **小步提交，信息写"为什么"**——每个提交可独立回退；提交信息不止写做了什么，还写根因与取舍 | 全部提交遵循 Conventional Commits，fix 类提交附根因分析 |

### 系统设计：怎么设计出好玩的系统

| # | 心得 | 证据 |
| - | ---- | ---- |
| P6 | **玩法支柱收敛决策**——把项目收敛为 2~3 条支柱，新功能立项先问"服务哪条支柱"，答不上来就砍 | 三条支柱（元素即流派/章节即旅程/猎人式探索）写在 GDD，所有设计向其对齐 |
| P7 | **机制与主题咬合**——核心机制从世界观里长出来，而不是贴皮：星辉增幅既是原著"星子连线"设定，又天然是增幅档位的视觉演出，教学成本和代入感一起赚 | 星辰增幅（对标歧路旅人 BP，但用星子连线重新表述） |
| P8 | **闭环思维：资源要有源头也要有去向**——设计任何资源先画完整回路：怎么获得、在哪消耗、消耗推动了什么。能赚没处花 = 断的回路，上线前必须补 | 金币/妖魔材料已能获得，商店未做前经济回路是断的——这正是 M3 前要补道具/商店/装备的原因 |
| P9 | **成长系统要制造决策，不只是制造数值**——好的成长让玩家"规划"，而不是"挂机"。瓶颈绑定狩猎目标，把练级变成每阶一次的主动决策 | 位阶制：突破需对应元素精魄（"要突破火系？去猎火系妖魔"），弃用无脑刷的经验值 |
| P10 | **输入一致性是体验底线**——输入方案作为硬需求一开始定死，别等做完再补；所有界面用同一套导航语言 | 键盘全程可玩是 M1 后补的（23fc00e），补齐成本不高但暴露了"输入需求没前置"；后定下"探索 WASD+E、战斗与菜单方向键+回车+Esc"的统一规范 |

### 工程：怎么让设计活下来

| # | 心得 | 证据 |
| - | ---- | ---- |
| P11 | **生命周期必须成对设计**——show/hide、lock/unlock、add/remove 成对出现；成对 API 的另一半散落在多处时就是坏味道，收尾要收敛到所有路径共用的层 | 踩坑 3（对话框残留）：收起只在 `choose()`，`say()` 路径永远不收 |
| P12 | **依赖显式化，不依赖隐式注册**——核心结构的引用走显式路径，不走全局类缓存/隐式约定/生成物 | 踩坑 2：`extends "res://..."` 与 `const X := preload(...)` 免疫缓存过期 |
| P13 | **不变量测试化**——坐标编码、数据格式、地图结构这类"约定"，要么写成断言、要么写进自动校验，不能只活在作者脑子里 | 踩坑 1：地图完整性冒烟（行数倍数、关键格可通行、传送门两端闭合） |
| P14 | **第二个实例出现时就抽象**——不必死等 Rule of Three：场景/地图类功能每多一个实例，复制一份的维护成本都翻倍；出现第二个同类实例就是抽基类的时机 | 踩坑 1：test_wilds 400 行独立实现收敛为 MapBase + 三张 62 行薄子类 |
| P15 | **信号总线解耦跨场景通信**——节点互不持有引用，跨场景事件走全局信号；全局状态只进 GameState，不散落全局变量 | `GameEvents` 信号总线 + `GameState` 单例的项目规范（README） |
| P16 | **数据驱动**——数值与内容配置用资源文件（.tres），调平衡不碰代码；代码只写"规则"，资源放"数据" | `resources/spells/`、`resources/monsters/`；`tools/generate_data.gd` 批量生成 |
